## Affected files

New:
- `configs/evaluation.yaml`: judge model/effort/prompt version/excerpt cap, freshness days, gate→evidence mapping (report globs, security case IDs, live-only gates, retrieval subset), bench settings, dataset paths. **No thresholds** (those stay in `eval_thresholds.yaml`).
- `app/evaluation/__init__.py`: eval-time package; nothing else in `app/` imports it ([spec: Architecture](spec.md#architecture-and-the-reason-for-it)).
- `app/evaluation/golden.py`: golden dataset loading and schema check; deterministic checks (citation validity, fabricated crypto guidance, secret scan); answers-file record builder with excerpt cap.
- `app/evaluation/judge.py`: judge payload builder (redaction, 300-character cap), verdict schema and parser, NOT JUDGED rules, metrics, calibration (agreement, Cohen's kappa), Batches client wrapper (imports `anthropic` lazily) and a fake client.
- `app/evaluation/bench.py`: `vllm bench serve` result parser and benchmark record.
- `app/evaluation/gate.py`: evidence discovery, freshness and dataset-version checks, per-gate grading, overall verdict, JSON and Markdown rendering.
- `app/evaluation/manifest.py`: deployment manifest schema, local field collection, completeness and no-identifier checks.
- `app/evaluation/setup_checks.py` *(added during step 9)*: helpers `scripts/setup.sh` calls through `uv run python -m`, so bash never parses YAML. They check the reference PDFs (presence, checksum, instructions), wait for the compose ports with a bounded timeout, and write the synthetic-only manifest.
- `evals/datasets/answer_golden.yaml`: 100 synthetic items (Claude drafts; developer reviews each).
- `evals/datasets/answer_golden.schema.json`: item schema.
- `evals/datasets/judge_calibration.yaml`: 20 item IDs (fixed seed) and the developer's grades.
- `scripts/eval_answers.py`: golden run (CI: `McpHarness` + `FakeLLM`; `--live`: real MCP, Qdrant, vLLM), writes `answers-<mode>-<ts>.json`.
- `scripts/judge_answers.py`: judge over an answers file (`--batch-id` to resume; fake client only with `DEVGUARD_TEST_BACKENDS=1`), writes `judge-<ts>.json`.
- `scripts/bench_report.py`: parses copied `vllm bench serve` JSON into `bench-<ts>.json`.
- `scripts/eval_crash_resume.py`: runs `tests/integration/test_crash_resume.py`, writes `crash-resume-<ts>.json` (PASS/FAIL/NOT RUN).
- `scripts/export_alerts.py`: exports non-synthetic receiver deliveries to `alerts-<ts>.json`.
- `scripts/release_gate.py`: the release gate; writes `release-gate-<ts>.json` and the committed Markdown report.
- `scripts/deploy_manifest.py`: fills local fields of the manifest, merges a setup report, checks completeness.
- `scripts/setup.sh`: the 13-step setup script; writes `setup-<ts>.json`.
- `docs/p9-final-evaluation-packaging/deployment-manifest.yaml`: committed manifest.
- `docs/p9-final-evaluation-packaging/runbook.md`: live-session order, the `vllm bench serve` commands, the judge and calibration steps, the controlled alert test, and the screenshot checklist.
- `docs/p9-final-evaluation-packaging/release-report.md`: generated by the gate (the generated block only).
- `docs/p9-final-evaluation-packaging/final-report.md`: final report, at most 5 pages, with the Mermaid diagram.
- `docs/p9-final-evaluation-packaging/screenshots/*.png`: the developer's reviewed screenshots.
- `tests/unit/test_eval_config.py`, `test_eval_isolation.py`, `test_eval_thresholds_pin.py`, `test_golden.py`, `test_judge.py`, `test_bench.py`, `test_gate.py`, `test_manifest.py`, `test_setup_checks.py`, `test_readme.py`, `test_final_report.py`: unit tests.
- `tests/integration/test_eval_answers_cli.py`, `test_judge_answers_cli.py`, `test_bench_report_cli.py`, `test_eval_crash_resume_cli.py`, `test_export_alerts_cli.py`, `test_release_gate_cli.py`, `test_deploy_manifest_cli.py`, `test_setup_sh.py`: subprocess tests of the real entry points.
- `tests/fixtures/evaluation/`: fixture reports (retrieval, flows, validators, security, answers, judge, bench, crash-resume, alerts, healthcheck, setup), a fake toolchain for `setup.sh`, and a small golden dataset.
